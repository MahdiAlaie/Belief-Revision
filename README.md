# آزمایشگاه بازنگری باور — نمونه‌ی مرجع دقیق

این مخزن کوچک، شروع فاز عملی پروژه‌ی بازنگری باور است. هدف milestone نخست، ساختن یک **oracle ساده و قابل‌راستی‌آزمایی** برای ورودی‌های کوچک است؛ هنوز قرار نیست سریع یا مقیاس‌پذیر باشد.

## تعریف مسئله در این نسخه

- `B`: پایگاه متناهی از فرمول‌های گزاره‌ای صریح.
- `φ`: اطلاعات تازه‌ای که باید پذیرفته شود.
- conflict kernel: زیرمجموعه‌ی کمینه‌ی `X ⊆ B` که `X ∪ {φ}` ناسازگار است.
- `Δ`: مجموعه‌ی فرمول‌های قبلی که حذف می‌شود.
- شرط سازگاری: `Δ` باید هر conflict kernel را قطع کند، یعنی `Δ ∩ X ≠ ∅` برای هر kernel `X`.
- هدف: پیدا کردن همه‌ی مجموعه‌های حذف با کمترین هزینه‌ی مثبت. اگر هزینه داده نشود، هزینه‌ی هر فرمول ۱ است؛ جمع هزینه‌ها با `Decimal` و بر مبنای نمایش متنی مقدارهای ورودی مقایسه می‌شود تا tieها بی‌دلیل با خطای اعشاری شکسته نشوند.
- خروجی: `φ` به باورهای باقی‌مانده افزوده می‌شود. اگر ورودی خودش ناسازگار باشد، خطای صریح می‌گیریم.
- پیش‌شرط: پایگاه اولیه‌ی `B` نیز باید سازگار باشد؛ تعمیر تناقض‌هایی که پیش از ورود `φ` در خود `B` وجود داشته‌اند، در دامنه‌ی این نسخه نیست.

این نسخه مستقیماً مدل پایه‌ایِ متناهی و تعارض‌محور را اجرا می‌کند؛ ادعا نمی‌کند همه‌ی postulateهای AGM را ارضا کند. هزینه‌ی دستیِ ورودی هم **entrenchment یا centrality نیست** تا وقتی نگاشت نظری و ساخت گراف جداگانه تعریف شوند.

## مثال دستی

```text
B = {a, b, (a ∨ b) → q}
φ = ¬q
```

اگر `a` درست باشد و قاعده‌ی `(a ∨ b) → q` برقرار باشد، `q` نتیجه می‌شود؛ همین‌طور برای `b`. بنابراین دو conflict kernel داریم:

```text
{a, (a ∨ b) → q}
{b, (a ∨ b) → q}
```

برای سازگارشدن با `¬q` باید از هر kernel دست‌کم یک عضو حذف شود. با هزینه‌ی یکنواخت، حذف قاعده‌ی مشترک یک جواب بهینه است. اگر هزینه‌ی حذف قاعده را ۵ و هزینه‌ی `a` و `b` را هر کدام ۱ قرار دهیم، حذف `{a,b}` ارزان‌تر می‌شود. این تغییر صرفاً اثر تابع هزینه است؛ به‌خودی‌خود به معنی «اهمیت واقعی» یا «استحکام معرفتی» نیست.

## اجرای مثال و تست‌ها

از ریشه‌ی پروژه:

```bash
PYTHONPATH=src python3 examples/manual_example.py
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

وابستگی بیرونی لازم نیست؛ فعلاً فقط از کتابخانه‌ی استاندارد Python استفاده شده است.

## اجزای کد

- `src/belief_revision/logic.py`: AST فرمول‌ها، ارزیابی فرمول و truth-table satisfiability oracle.
- `src/belief_revision/exact.py`: استخراج kernelها، enumeration همه‌ی hitting setهای نامزد و اجرای عملگر نمونه.
- `tests/test_exact.py`: آزمون semantics، minimality، بهینگی، سازگاری خروجی و حالت‌های مرزی.
- `examples/manual_example.py`: بازسازی مثال دستی با اجرای کد.

## محدودیت آگاهانه‌ی نسخه‌ی اول

اگر `v` تعداد متغیرهای اتمی باشد، truth-table oracle تا `2^v` تفسیر را بررسی می‌کند. استخراج kernel و یافتن مجموعه‌های حذف نیز حالت نمایی دارند. این رفتار برای نمونه‌های کوچک و مقایسه‌ی نسخه‌های بعدی با oracle مفید است؛ برای ادعای سرعت یا مقیاس‌پذیری کافی نیست.

### هنوز پیاده‌سازی نشده

- parser متنی برای واردکردن فرمول‌ها؛ فعلاً فرمول‌ها با AST پایتونی ساخته می‌شوند.
- گراف وابستگی و تعریف یال/مرکزیت.
- روش SAT/MaxSAT یا الگوریتم مقیاس‌پذیر.
- اعتبارسنجی تمام postulateهای AGM یا ادعای معادل‌بودن با یک عملگر استاندارد.

## معیار تکمیل milestone اول

1. همه‌ی تست‌ها پاس شوند.
2. مثال چاپ‌شده با حل دستی kernelها و حذف کمینه مطابقت کند.
3. با هزینه‌های دستی متفاوت، اثر انتخاب هزینه به‌صورت قابل‌پیش‌بینی نشان داده شود.
4. هیچ ادعای گرافی یا کارایی پیش از پیاده‌سازی و آزمایش آن مطرح نشود.
